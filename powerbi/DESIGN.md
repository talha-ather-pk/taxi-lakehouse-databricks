# Calder City taxi dashboard: design and implementation notes

Everything is generated by [`scripts/build_pbip.py`](../scripts/build_pbip.py). Re-run it after changing the script, open
`CalderTaxi.pbip` in Power BI Desktop (November 2025 release or later) and click **Refresh**. The data folder is the
`DataFolder` parameter (Transform data → Edit parameters); it points at `data_clean/gold/`, the gold tables exported by
`scripts/run_local.py`. On Databricks, replace each table's source with the `workspace.taxi_gold` table of the same name
(Get data → Azure Databricks); the model, measures and pages stay the same.

Same executive design system as the other portfolio dashboards: custom theme `theme/Calder_Executive.json`, navy sidebar
navigation with synced filters, live filter line under each page title, KPI tiles with a comment line, and a title plus a
one-line takeaway on every visual.

## Data model

```
                 dim_month ─── dim_date (from the weather table: rain, holiday, weekday, fee period)
                   │    \          │        \
                   │     \   fact_zone_daily  fact_downtown
   fact_hourly ────┤      \        │
   fact_payment ───┤   dim_daytype dim_zone ── dim_borough ── fact_flows
   fact_flows ─────┘
   data_quality, pipeline_batches, findings (stand-alone)
```

| Table | Grain | Gold source |
|---|---|---|
| `fact_zone_daily` | pick-up zone × day | `zone_daily` (trips, revenue, fares, tips, distance, duration, card trips/fares/tips) |
| `fact_hourly` | month × weekday/weekend × hour | `hourly_demand` (with the number of days, so trips per hour is exact) |
| `fact_payment` | month × payment type | `payment_summary` |
| `fact_flows` | month × pick-up borough × drop-off borough | `borough_flows` |
| `fact_downtown` | day × segment (touches Downtown / elsewhere) | `downtown_daily` |
| `dim_date`, `dim_zone`, `dim_borough`, `dim_month`, `dim_daytype` | | `silver.weather`, `silver.zones`, generated |
| `data_quality`, `pipeline_batches`, `findings` | | pipeline logs and `05_analysis` results |

Gold stores **sums** (distance, duration, card fares, card tips) next to the averages, so every average in the report is
recomputed exactly at the level shown (for example speed = Σ miles ÷ Σ hours, not an average of daily averages).

## Pages

| Page | Question | Visuals |
|---|---|---|
| **Overview** | How big is the business, and where does revenue come from? | 5 KPI tiles, daily trips with rainy days in gold (day tooltip), revenue by borough, zone ranking |
| **Demand & Traffic** | When do people ride and how slow is traffic then? | Hour × day-type heat strip, demand curve, speed by hour, dry vs rainy days by weekday |
| **Downtown Fee** | Did the $2.50 congestion fee (from 1 March) reduce Downtown trips? | Effect (difference-in-differences), Downtown share before/after, weekly ratio before vs after, monthly index, before/after table |
| **Payments & Zones** | How do riders pay and tip; where do trips go? | Payment mix, card share trend, tips by payment type, borough flow heat map, revenue per trip by borough |
| **Data Pipeline** | Can the numbers be trusted? | Raw → rejected → duplicates → clean KPIs with a reconciliation check, rejection reasons, every check vs the injected truth, pipeline runs (files, inserted, updated, months rebuilt) |
| **Zone Detail** (drill-through) | Everything about one pick-up zone | Zone KPIs, daily pick-ups, weekday pattern, zone profile |
| Day (tooltip) | Hover detail for a date | Trips, revenue, speed, rain, holiday |

## Using it

* **Navigate:** sidebar menu (Ctrl + click in Desktop; plain click once published).
* **Drill through:** right-click a zone in the ranking → **Drill through → Zone Detail**; the back arrow returns.
* **Filters:** Month, Pick-up borough and Day type are synced across pages. The Downtown-fee effect and the pipeline
  checks are whole-dataset results and do not change with filters.
